Flotilla feature matrix

Flotilla's feature set, grouped by the areas of the pasted outline and expanded with capabilities found in the codebase. Status values:

  • Implemented — reachable in the app today.
  • Partial — present but limited, gated behind configuration, or dependent on the relay/native platform.
  • Not implemented — no code path exists.
  • By design — supplied by the Nostr protocol or the deployment model rather than by app code.

Notes point at the route or module that carries the feature; US-nnn refers to the story catalog in e2e/USER_STORIES.md.

Portable identity & history

Feature Status Notes
Customer holds keys By design Identity is a self-sovereign nsec/npub; no account lives with the operator
Customer holds source and data By design Self-hostable relay plus user-chosen relays; events are portable Nostr events
One-click export / import Not implemented No bundled export or re-import of a user's data
Multi-device sync Implemented NIP-78 app-data sync, app/sync.ts; read state and settings follow the account
Local-first history Implemented IndexedDB persistence, app/storage.ts, lib/indexeddb.ts; read conversations survive relay loss. US-109
Account portability across clients By design The same keys and relay events work in any NIP-29 client
Key recovery Implemented KeyRecoveryRequest.svelte, KeyRecoveryConfirm.svelte for custodial (Pomade) accounts
